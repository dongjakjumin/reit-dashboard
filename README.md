# 리츠 현황판

국토교통부 리츠정보시스템(reits.molit.go.kr)의 공개 자료를 영업일마다 한 번 받아 정적 HTML로 만드는 개인 프로젝트입니다. 화면은 네 장입니다.

| 화면 | 주소 | 내용 |
|---|---|---|
| 인가와 프로젝트리츠 | https://dongjakjumin.github.io/reit-dashboard/ | 접수현황, 신규 인가·등록·신고 추이, 프로젝트리츠 목록, 자산관리회사별 현황 |
| 상장리츠 | https://dongjakjumin.github.io/reit-dashboard/listed.html | 주가, 시가총액, 기간 수익률, 배당률, P/NAV, P/FFO(연환산), WALE |
| 재무 구조와 공시 | https://dongjakjumin.github.io/reit-dashboard/finance.html | 상장리츠의 자산·부채·자본과 추이, 전체 리츠의 주요 수시공시 |
| 사업성 계산기 | https://dongjakjumin.github.io/reit-dashboard/calc.html | 임대형 개발사업의 총사업비, 조달, 매각과 운영 후 매각 비교, 프로젝트리츠 점검표 |

## 실행

파이썬 3.10 이상이면 되고, 설치할 패키지는 없습니다. 계산기 검산에만 node가 필요합니다.

```
python collect.py            # 수집: data/ 아래에 저장
python tests/calc_check.py   # 사업성 계산 엔진 검산(node 필요)
python build.py              # 화면 생성: site/ 아래 HTML 네 장
python verify.py             # 배포 전 점검: 합계, 원문 재조회, 재계산, 개인정보
```

`run_daily.bat`은 수집, 화면 생성, 점검을 차례로 실행하고 결과를 `logs/run.log`에 남깁니다. 내 PC에서 직접 돌려 볼 때 씁니다. 정기 수집은 GitHub Actions가 맡습니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `reits_api.py` | 리츠정보시스템 조회 화면과 같은 요청을 보냄. 요청 사이 2.5초 간격, 실패하면 간격을 늘려 다시 시도 |
| `collect.py` | 운영 중 리츠, 접수현황, 상장리츠 지표와 종가, 상장리츠 재무(주 1회), 수시공시를 받아 저장 |
| `build.py` | 집계 후 템플릿 네 개(`template*.html`)에 넣어 `site/` 아래 HTML 생성. 공통 스타일은 `style.css` |
| `verify.py` | 배포 전 점검. 숫자가 하나라도 어긋나면 종료 코드 1 |
| `textutil.py` | 수집과 집계가 같이 쓰는 글자 처리(최대주주 칸의 개인 이름 모양 값 지우기) |
| `calc_engine.js` | 사업성 계산 엔진. 화면과 검산이 같은 파일을 씀 |
| `calc_defaults.json` | 계산기 기본 가정(가상의 오피스 개발 예시)과 나빠진 가정의 폭 |
| `tests/calc_ref.py`, `tests/calc_check.py` | 같은 계산 규칙의 파이썬 참조 구현과, 두 구현을 경계에 가까운 가정과 무작위 가정 400가지로 대조하는 검산 |
| `config.json` | 강조할 자산관리회사, 화면 아래 표기할 이름과 연락처 |
| `data/snapshots/` | 날짜별 수집 원자료. 지우지 않고 쌓음 |
| `data/filings_log.json` | 접수 건별 기록(처음 본 날, 진행상태 변화, 목록에서 빠진 날과 그날 확인한 결과) |
| `data/prices.json` | 상장리츠 종목별 일별 종가. 종목별로 하루 한 번 조회해 지난 거래일의 종가를 반영 |
| `data/financials.json` | 상장리츠의 자산, 부채, 자본과 결산기별 추이 |
| `data/disclosures.json` | 수시공시 누적 기록(최근 1년) |

## 원칙

- 화면이 열릴 때 AI나 외부 서비스를 부르지 않습니다. 같은 자료면 같은 화면이 나옵니다.
- 공개 자료만 씁니다. 접수현황 응답에 들어 있는 신청 담당자 이름과 연락처는 저장하지 않고, 개인으로 보이는 최대주주 이름은 가립니다. 임원과 자산운용전문인력 변경 공시, 사유에 ‘주주’가 들어간 공시는 본문을 비웁니다.
- 평일 오전 10시에 기본 목록을 먼저 저장합니다. 시세, 재무, 공시는 각각 갱신합니다. 갱신에 실패한 파일은 이전 자료를 유지합니다. 상장리츠 재무 자료는 주 1회만 다시 받습니다.
- 숫자는 배포 전에 `verify.py`로 원문과 대조합니다. 원문 접속이 안 돼 재조회를 못 한 항목은 건너뛴 것으로 적고, 점검에 실패하면 배포를 중단합니다.
- 계산기는 수집 자료를 쓰지 않고 입력값을 어디로도 보내지 않습니다. 기본값은 가상의 예시입니다.

## 배포

- `.github/workflows/daily.yml`이 평일 10:00(KST)에 수집합니다. 저장한 JSON에서 전화번호가 발견되면 커밋 전에 중단합니다. 개인정보 점검을 통과하면 수집 자료를 커밋하고 계산 엔진 검산, 화면 생성, 점검을 거쳐 GitHub Pages에 올립니다. 점검에서 숫자가 어긋나면 배포만 막고 그날 수집 자료는 남깁니다.
- 수동 실행에서 `deploy_only`를 켜면 원문에 접속하지 않고 저장된 자료로 화면만 다시 올립니다.
- 주소 끝에 `?amc=회사이름`을 붙이면 자산관리회사별 표에서 그 회사 행을 강조합니다.
- 계산기는 바꾼 가정이 주소에 붙으므로, 주소를 복사하면 같은 가정을 다시 열 수 있습니다.

## 알려진 한계

- 리츠조회 목록에는 해산하거나 인가가 취소된 리츠가 없어, 과거 연도의 신규 건수는 현재 운영 중인 리츠만 센 값입니다.
- 상장리츠 종가는 수정주가가 아닙니다. 기준가가 바뀐 날을 사이에 둔 수익률은 비워 둡니다. 과거 종가는 일별 이력에서 받습니다. 당일 종가는 목록의 시세 기준 시각이 15시 40분 이후일 때만 저장합니다.
- 재무 수치는 리츠 한 곳의 별도 기준이라, 자리츠나 펀드를 거쳐 자산을 보유하는 리츠는 부채가 작게 나옵니다.
- 배당률은 납입자본금 기준입니다. 주가 기준 시가배당률은 주당 배당금 자료가 있어야 합니다.
